# QDS Framework Simulation Datasets

This directory contains the integration event contracts (.json) generated by the core pipeline (Person 1) for consumption by the Attack Simulation suite (Person 2) and the Frontend Dashboard (Person 3).

## Files Generated
- simulation_events.json: The baseline honest run (0 noise, 0 attacks). Expect 0 REJECTs.
- simulation_events_intercept.json: Triggering decoy_qber_exceeded and cefb_exceeded.
- simulation_events_entangle.json: Triggering decoy_qber_exceeded and cefb_exceeded.
- simulation_events_replay.json: Triggering eplay_detected.
- simulation_events_batchNoise.json: Triggering cefb_exceeded.
- simulation_events_blind.json: Triggering hardware_integrity_failure.

## Important Implementation Notes
> **Note on status field:**
> This dataset simulates the forward signing channel only. The asynchronous confirmation sweep network logic (§2.7) is not simulated in this offline payload, so the status will remain "PROVISIONAL" across all events. 
> Person 3: You do not need to build your live Charlie panel to expect CONFIRMED or DISPUTED transitions based on these datasets.

> **Note on Validator Aggregate Warnings:**
> If you run alidate_events.py against the attack-specific JSON files, the validator will correctly output an error complaining about a 100% REJECT rate. The validator's aggregate check assumes a *no-attack* run. Do not be alarmed by this; the spike in REJECTs is exactly what we want in the attack datasets to confirm detection logic works.
